Point Lights — Stage 1

Canon 53 — the engine, the brazier, and the ghost that shows you what it will light.

1. What shipped, and what deliberately did not

Shipped: DungeonPointLight, a placeable light path through the existing furniture system, a placement radius ghost, and Log Point Lights.

Not shipped, on purpose: road lamps, dormant site torches, dwarven hold lights, the holy blue. All four are decided and written into canon 53 so they are not re-argued — but the additive disc has no occlusion and nobody has yet seen one of these in the dark. Validating one light before scattering several hundred is the same rule the art guide applies to an emblem batch, applied to a system.

The one thing that cannot be answered from source: whether a lamp beside a wall visibly glows through into the void on the far side. Radius discipline is the mitigation (3–4 cells). If it reads wrong, the recorded upgrade is a baked per-light shadow mask — not a reason to abandon the approach.
2. How it works

The shader was already the answer. DCR/AdditiveSprite blends OneMinusDstColor One — a screen blend, contribution src * (1 - dst). A light is darkness removed: full strength over the void fill, nearly nothing over ground already at claimedLight, bounded so it can never clip to white. That single property is the whole balancing model, and it is why the same lamp needs no per-context tuning.

Sprites, not the light map. DungeonShadow paints one flat colour per cell, so a point light strong enough to see draws as concentric 32px blocks — the cursor light hit this years ago and its own comment records the fix. Nothing reads baseLight for gameplay, so entering the map buys no mechanics and costs a disc walk on every claim. The static registry on DungeonPointLight is where a gameplay hook attaches if light is ever given teeth.

Sorting. Shadow layer, order 4 — above the void fill (0), below the cursor light (5), below the fog (10). Fog still occludes, which is what will let stage 2 spawn lamps on reveal without leaking floor layout.

Flicker is phased off position, not Time or Random: a row built in one frame would otherwise pulse in unison and read as one flashing object. Position is stable across a reload too, so nothing jumps phase on load. Gated on SpriteRenderer.isVisible.

The player's light is furniture, which is why this stage is small. Placement on any mined cell, mana cost, half refund, save and restore-by-name are all already shipped. No new build mode, no new UI, no save migration. RoomValidator matches by exact definition reference, so a brazier can neither satisfy nor pollute a room requirement.

The ghost is the Phase 9 preview, pulled forward and scoped. It reuses spellGhostSR and GenerateDiscSprite. The spell pass runs first and disables the ghost whenever CastSpell is not current; UpdateFurnitureGhost returns without touching the renderer when its own mode is not current, so the two never fight. Radius and colour are read off the prefab, never a copy on the definition — a ghost that eventually lies about the lamp it previews is worse than no ghost.
