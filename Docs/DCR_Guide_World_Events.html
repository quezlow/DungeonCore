World Events

Canon 37 — the world's weather: a data-driven dispatcher rolling small random events at dawn, so a new event is an asset entry rather than a component. Ships with the murrain, the pilgrim surge, and the tremor.

1. What shipped, in one breath

WorldEventDirector (one component beside the threat managers) self-populates from Resources/Events/World and rolls each dawn: tick the active timed effects, burn the global cooldown, gather eligible events, roll a daily fire chance of 0.25, then one weighted draw. Global cooldown 3 days between any two events; the tuning lands 4–5 events per 30 eligible days, validated across seeds by Tools/sim_world_events.py (14 checks). The C# mirrors that file's dawn ordering exactly — the sim is the specification.

Deliberately greenfield. The four bespoke threats (HolyOrderStrike, MercenaryContract, NobleRetaliation, WildMonsterEvent) are byte-identical to before this arc: each is a tuned state machine, and a registry generic enough to hold them would be a rewrite of tuned behaviour for no player-visible gain. The Wandering Merchant keeps its own arrival controller. The hostile flag on a definition is the slot a future assault-shaped event uses to honour SuppressMidGameThreats; none of the v1 trio carries it, so the world keeps its weather even through the climax.

No autosave on fire. These are weather, not assaults — the threat components autosave because a raid is a run-defining moment; a two-day pilgrim surge is not.

3. The dawn machine

The order matters and is fixed; sim_world_events.py asserts it:

1. tick active timed effects   (decrement, expire, recompute multipliers)
2. global cooldown holds?      (decrement and stop -- nothing rolls today)
3. gather eligible events      (gates, per-event cooldown, not already
                                active; climax strips HOSTILE events only)
4. roll dailyFireChance        (0.25 -- most dawns are quiet)
5. one weighted draw, fire     (event + global cooldowns re-arm)
