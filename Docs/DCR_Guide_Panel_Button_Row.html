The Panel Button Row

Canon 40 — eight windows that had no on-screen affordance at all, plus the seven over-gated sites the pause audit's first pass missed. The two ship together, because a button that visibly does nothing is a bug report where a dead hotkey is merely invisible.

1. Why this, and why now

Eight actions were keyboard-only: traps, alerts, loot, journal, known parties, factions, research, recenter on core. A player who never opens the keybind screen cannot find the research tree or the bestiary. That's most of the UI surface hidden behind unlabelled keys — a bigger player-facing hole than anything else on the board, for a fraction of the cost.

The audit that preceded this was incomplete, and I own that. Canon 39 scoped itself to "the eight sites above, nothing else" — but that list came from a resource-spending grep plus the panels I happened to read alongside it, not from an exhaustive sweep of PauseController.IsGamePaused. It fixed four over-gated openers and missed seven more of the identical class. Building the row is what surfaced them: five of the eight buttons would have visibly done nothing while paused.

Canon 39 now records that its first pass was partial, rather than being quietly corrected. An audit bounded by the evidence already in hand is not an audit.

2. The completed sweep

Seven sites, all now ungated:

LootPanel, KnownPartiesPanel, FactionPanel, AlertHistoryPanelWindow hotkeys refused while held — though the journal and research tree never carried a gate. That inconsistency was the tell.

That last one was hiding a real defect. The hover cost preview keys off CurrentMode. With mode entry gated, the preview was only reachable if you'd entered the mode before pausing — half of last arc's feature, invisible in the exact situation it was built for.

Only the four hotkeys moved above the gate. The Esc-cancel block below it stays put: it coordinates with PauseMenuController's chain, and freeing it is a separate question from window availability. Deleting the gate outright would have changed Esc behaviour as a side effect.

Confirmed correct and deliberately untouched: the journal, research, recenter, minimap click-to-pan and the speed keys carry no gate and shouldn't; HotbarController gates correctly because it calls item.UseItem(), which acts; every simulation tick gates correctly; and the guards in MenuController and PrologueSettingsHotkey stay, because "don't open over another pause holder" is a different concern that the availability rule would break if applied to it.

3. The row itself

One new file, Assets/Scripts/UI/PanelButtonRow.cs. Separate from ActionBarHUD on purpose — that bar selects a tool, this row opens a window. Mixing them would make the action bar's selected-tab highlight meaningless.

Built in code, not wired in the scene. AlertHudButton is the behavioural precedent and it's scene-wired, but replicating that eight times is eight sets of Inspector references and eight silent failure modes. Silent failure is designed against here, so the row builds its own children and takes only sprites from the Inspector.

Locked buttons are hidden, not greyed. A greyed button for a system the player has never heard of is a spoiler and a dead click. Re-applies on UnlockState.OnChanged.

Each button shows its bound key underneath, from Keybinds.DisplayName, refreshed on Keybinds.OnRebind. The row teaches the hotkey rather than replacing it.

Alerts alone carries a badge. It's the only one of the eight with an existing unread count. Badges for the rest would mean inventing the counters first, and an invented counter is a number nobody can trust.

Temp icons are fine. Any button whose sprite slot is empty falls back to its text label — the same degradation ActionBarHUD's submenu entries already use. An unstyled row reads as eight names, not eight blank squares.

6. Notes for next time

The pause menu is not in the row. GameAction.AvatarMenu is a misnomer — MenuController toggles menuCanvas and pauses the game. It's the pause/settings menu, it duplicates Esc, and it isn't a dungeon window. Worth renaming the enum label some day; the enum value must not move, since bindings persist under the name.

The influence overlay stayed out of the row by your call, but its gate was fixed anyway — the hotkey now works while held.

Icon debt. Eight temp icons here join the nine core-spell icons already outstanding. Icons sit second in the asset order behind props and decor.

Minimap has a Toggle() and a collapse button but no hotkey, so it sat outside this arc entirely. If you ever want it keyboard-accessible, that's a new GameAction appended to the enum and one more row entry — both cheap.
