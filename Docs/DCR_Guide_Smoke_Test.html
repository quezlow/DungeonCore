Comprehensive Smoke Test

289 commits since 06f1b350 (22 Jul). Thirty-eight canon entries and a dozen loose items, none of them tested in a whole run.

0. How to use this, and what it does not cover

Ordered by session flow, not canon number — prologue, then the opening, then outward and downward, then the late game. Testing in canon order would bounce between floors and game phases on every item and pay the setup cost each time.

Each chapter opens with the readouts and only then asks you to look at anything. That ordering is the point: a readout that proves the state is right before you judge the behaviour costs seconds, and judging behaviour on a state you assumed costs a session.

Steps marked EYE have no diagnostic at all and can only be judged by looking. About twenty of the fifty areas are in that bucket, and that is where your time will actually go. Each one carries a one-line correct looks like drawn from canon rather than from taste.

When something fails, run the named diagnostic before writing it up. Every step that has one names it. "It doesn't work" plus a readout costs one round trip; "it doesn't work" alone costs two, and the second one is spent discovering which of six causes it was.

1. Pre-flight — validators, generators, wiring

A stale generated asset reads exactly like a system bug. Everything here is cheap and runs with play mode stopped.

2. Fixtures — build five states once, re-enter them freely

Five fixtures in slots 6–10, so your real runs keep 1–5. Snapshots are byte copies of a slot folder parked under a label at Saves/snapshots/<label>/, so re-entering a state is a copy back rather than a replay.

Snapshot in play modeRestore with play mode STOPPED
Snapshot Slot flushes the game with a real save first, then copies.Restore Slot refuses while the application is playing — a pending autosave would clobber the restored file mid-fade. Refusing by construction beats winning a race.
Restore auto-snapshots first. Before overwriting, the current slot is captured to _prerestore. Restoring on top of a state you meant to keep is recoverable exactly once, so do not lean on it.

16. Save and load — the highest-value chapter

Roughly forty new persisted fields landed since the baseline and CURRENT_VERSION is still 3. That is a load-bearing claim — every one of them is additive and defaults cleanly on an older save — and it has never been checked once.

Canon's own lesson applies here. The ReassertOpenGround fault was invisible on fresh generation because the site pass "measured this clean by hand because it never reloaded". Ground came back revealed but not open, and dug ground came back under fog with wall caps beneath. Validate Reveal Consistency is the standing check — run it after a LOAD, not after a generate.
17. Defect log

One line per defect, and paste the readout. Format that survives a handoff:

CHAPTER / STEP   what you did
EXPECTED         one line, from the guide
OBSERVED         one line, what happened
READOUT          the output of the named diagnostic
FIXTURE          which snapshot label, so it can be re-entered
The fixture label is the part people drop and the part that matters. A defect that can be re-entered by restoring a snapshot costs one round trip to fix. One that has to be reproduced by playing forward costs a session, and sometimes cannot be reproduced at all.
